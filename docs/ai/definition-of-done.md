# Definition of Done (DoD)

タスクを「完了」とみなす条件。AGENTS.md からポインタ参照される。

AI エージェントは作業終了前にこのチェックリストを **機械的に走らせる** こと。

---

## 必須項目

すべて満たして初めて「完了」とみなす:

### 1. コードが意図通り動く
- [ ] 該当する機能を手動 (or 自動テスト) で動かして確認した
- [ ] 既存機能を壊していない (`./gradlew test` 全緑)

### 2. テストが追加/更新されている
- [ ] 振る舞いを変えたなら、対応するテストがある
- [ ] テストは **正常系・異常系・境界値** をカバーしている
- [ ] テスト名が「何を検証しているか」を表している

### 3. ビルドが緑
- [ ] `./gradlew build` がエラーなし
- [ ] `./gradlew test` が緑

### 4. アーキテクチャ規約に従っている
- [ ] `docs/ai/architecture.md` の層構造を守っている
- [ ] `docs/ai/code-review.md` のチェックリストをセルフレビュー済み

### 5. ドキュメントが整合している
- [ ] 公開 API を変えたなら、関連 docs を更新した
- [ ] AGENTS.md / `docs/ai/*` への影響があれば反映した

---

## 完了報告フォーマット

AI エージェントは作業完了時に以下を **必ず** 出力する:

```
## 変更ファイル
- <ファイルパス>: <何をしたか 1 行>
- ...

## 実装した振る舞い
- <受け入れ要件 1>: ✅ 実装済み (テスト xxx で検証)
- <受け入れ要件 2>: ✅ 実装済み
- ...

## 実行したテスト
./gradlew test
→ BUILD SUCCESSFUL — N tests passed, 0 failed

## 残るリスク
- <考慮しきれなかった点 / 既知の制約>
- 「特になし」と書くのではなく、本当に何もなければ「リスク: なし」と明示

## 関連ドキュメント更新
- <ある場合のみ>
```

---

## やってはいけないこと

- ❌ テストを書かずに「完了しました」と報告
- ❌ ビルドエラーを残したまま完了報告
- ❌ 「テストは皆さんで実行してください」と完了を投げる
- ❌ リスク欄を省略する (必ず書く、無ければ「なし」と明示)
- ❌ 変更ファイル一覧を省略する

---

## チェックリスト走らせ方 (Claude / Codex 共通)

タスク終盤に以下のプロンプトを自分に向けて投げると確実:

```
DoD チェック:
1. 全テスト緑か?
2. 変更ファイル一覧を出した?
3. 受け入れ要件のチェックリストを出した?
4. 残るリスクを明示した?

全部 Yes なら完了報告を最終形で出す。
1 つでも No なら、それを満たしてから報告する。
```
